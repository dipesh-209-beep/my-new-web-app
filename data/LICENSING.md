# Data Licensing and Provenance

**Last reviewed: 2026-09-27**

The project's *code* is MIT licensed (see the root `LICENSE`). The *data* is
not, entirely, and this file exists because those are two separate questions
that a single root `LICENSE` file cannot answer.

Read this before redistributing the dataset, publishing a derived dataset, or
attributing the project.

## Summary

| Source | License | Obligation on us |
|---|---|---|
| OpenStreetMap (incl. Overpass Turbo exports) | **ODbL 1.0** | Attribution **and** share-alike for derived databases |
| Yatayat (Kathmandu University Geomatics / Monsoon Collective) | Community project built on OSM data — **inherits ODbL**; the site's own terms are unverified | As above, plus check the source's terms |
| Nepal DOTM registration records | Government records, presumed open for reuse — **terms unverified** | Verify before redistributing |
| Fares | **Desk estimates by this project, not field-verified** | Must be labelled as estimates |
| Congestion tables in this repo | Derived/authored by this project | No external terms |

**The obligation that matters:** because most of the dataset derives from
OpenStreetMap, the derived database is ODbL. Publishing a modified/derived
database — including a hosted instance serving the data as an API — triggers
ODbL share-alike: you must offer the database under ODbL, and you must
carry attribution. This is stricter than the MIT terms on the code and is
not satisfied by the root `LICENSE` alone.

This is a summary for orientation, not legal advice. ODbL is a specific legal
code with defined terms; read it, and take advice if you are deploying
publicly.

## What that means in practice

- **Keep the code and the data terms separate.** The MIT `LICENSE` covers
  `backend/`, `frontend/`, `data/scripts/`, and the migrations. The data
  files are ODbL-derived. Do not relicense the data under MIT.
- **Attribution.** Any user-visible surface built on this data should
  credit OpenStreetMap contributors. The frontend map already does; the
  root README should too.
- **Offer the database as ODbL.** If you run a public instance, ODbL §4(b)
  means offering the database under ODbL to anyone who asks. Hosting the
  app and offering a download is the usual way to satisfy this.
- **Keep provenance.** `data/raw/README.md` records where each file came
  from. Do not lose it — it is what makes compliance demonstrable.

## Unverified items

These are flagged rather than asserted, because the project's own data
audit found them:

- **Yatayat terms.** The Yatayat project is a community mapping project; its
  site may or may not carry its own terms on top of the OSM data underneath.
  Unchecked.
- **DOTM records.** `operators.csv` and `route_operators_production.csv` were
  transcribed from public DOTM records. Public availability is not the same
  as open licensing. Unchecked.
- **Fares are estimates.** The `fare_rules` table is a desk estimate, not
  field-verified (see the audit note in `data/README.md`). Do not present
  fares as authoritative; label them as estimates.

## Provenance

The per-file breakdown of sources, methods and dates lives in
`data/raw/README.md`. The pipeline that turns those raw files into the
importable CSVs is documented in `data/README.md` and
`data/scripts/README.md`.

Do not edit `data/processed/*_clean.csv` by hand — they are regenerated by
`data/scripts/clean_data.py` from `data/raw/`, and an edit is silently lost
on the next run. That is why edits belong in the cleaning script or in a
documented dedup override.
